# 车牌录像 · Android 1.7

安装包：`output/PlateJournal-1.7.apk`。适用于 Android 8.0 以上 ARM 手机，使用 HyperLPR3 Android SDK 离线识别。

本版沿用旧版包名和签名，可直接覆盖安装。**不要先卸载，否则应用专属目录中的录像会被删除。**

## 1.7 更新

- 预览界面增加镜头选择，列出 Camera2 开放的摄像头 ID、朝向和焦距；可切换前置、后置及其他独立开放的镜头。
- 每个镜头分别查询录像分辨率、ISO、快门和补光灯能力；不兼容的手动曝光或码率恢复自动，分辨率选择可用尺寸。
- 录制期间禁止切换镜头；切换时关闭补光灯。前置预览取消镜像以保持车牌文字方向。
- 厂商未向第三方独立开放的副摄不会显示；此版本不支持同时录制多个摄像头。
- 需要真机验证各镜头横竖屏预览、绿框位置和录像播放方向。

## 1.6 更新

- 预览页新增“补光灯”开关，使用 Camera2 FLASH_MODE_TORCH 持续亮灯，适合录像。
- 预览和录制过程中均可开关，不中断录像；切换自动/手动曝光继续保留补光灯设置。
- 检查当前摄像头 FLASH_INFO_AVAILABLE，无闪光灯时禁用按钮并明确显示原因。
- 横竖屏和分辨率切换时保留本次拍摄的开关选择；离开拍摄、停止录像、锁屏或切后台时关闭灯。重新进入拍摄默认关闭。
- 闪光灯属于可选硬件，没有闪光灯的手机仍可安装应用。

## 1.5 更新

- 放宽 Camera2 判断：只检查 ISO 与曝光时间范围，不再因缺少 MANUAL_SENSOR 标记、帧时长范围或完整请求键列表而禁用手动选项。
- 不再强制提交 SENSOR_FRAME_DURATION，帧时长交由手机相机驱动处理。编码器仍请求 30fps，实际采集帧率由设备决定。
- 预览页直接提供“分辨率 / ISO / 快门”按钮。分辨率在未录制时可切换；ISO 与快门在预览和录制时均可调整，通过更新现有重复请求应用，不重启录像或重置帧时间原点。
- 从自动改为手动时，另一项优先沿用相机报告的当前值，并选择范围内最近可用档位；按钮显示设置值，顶部状态显示相机报告的实际值。
- “恢复自动曝光”会同时恢复 ISO 和快门自动。设备拒绝快捷设置时会尝试恢复前一请求并提示失败，不会把提交失败的值保存成成功设置。
- 横屏拍摄控制区可滚动，避免按钮被屏幕高度遮住。
- 索引中的 ISO / 快门字段记录录像开始时的设置，不包含后续每一次手动调整。

## 已有功能

- 横屏识别不再从 TextureView 缓冲区截图。优先读取独立的 YUV 摄像头画面，正确处理行步长、像素步长、裁剪、UV 顺序，再按传感器与显示方向转换成正向图像后送入 SDK。
- 如果手机不支持“预览 + 原始识别画面 + 录像”的并行组合，会重试两路输出，识别画面改为从实际显示的预览区域通过 PixelCopy 获取。失败会显示状态，不会使用空画面冒充成功。
- 增加“查看识别画面”，显示实际送入识别器的缩略图，方便核对方向、清晰度及内容。
- 增加码率、ISO 和快门设置；选项依据本机摄像头、编码器能力生成。
- **边录边保存车牌时间点和截图。停止录像不再自动扫描整段视频。** 停止时仅等待已提交的最后一帧识别与文件写入，再打开回放。

## 使用

1. 把 APK 传到手机，覆盖安装，允许摄像头权限。
2. 在“设置 · 录像与曝光”选择分辨率、码率、识别间隔和曝光模式。
3. 点击“开始拍摄”，横放或竖放手机；可直接使用分辨率、ISO、快门按钮调整。预览中绿色框标注最近识别到的车牌，顶部显示识别数量、耗时和相机报告的实际 ISO / 快门（设备提供这些数据时）。
4. 如果识别始终是 0 个，点击“查看识别画面”，检查车牌是否正向且清晰。这张图是送入识别器的实际画面，而非另取的一张截图。
5. 点击“开始录制”。录制过程中直接保存车牌号码、截图和视频时间。
6. 点击“停止并查看车牌”。无需等待整段扫描，写入完成后直接进入录像回放与时间线。
7. 拖动进度条查看附近时间点的车牌及截图；点击记录跳转，长按记录查看截图。
8. “识别此时间点”可以手动补查；“更多 → 手动补扫整个视频”是可选功能，会在确认后重建并替换本段索引，不会在录制结束时自动执行。
9. “更多 → 导出视频、截图和 CSV”把 MP4、截图、索引和表格导出为 ZIP。

## 录像与曝光设置

- **识别间隔**：0.1、0.25、0.5、1、2、5 秒，表示两次实时识别开始之间的最短间隔。手机性能不足时实际间隔会更长，不会排队积压所有帧。
- **分辨率**：读取当前所选摄像头的 MediaRecorder 输出及 H.264 surface 编码器的 30fps 支持能力。支持并开放 3840×2160 时显示 4K UHD。录像与预览采用独立尺寸，预览最高 1080p。
- **码率**：自动，或选择编码器支持的具体 Mbps 值。分辨率变化后列表重新计算。码率是编码目标值，实际文件大小可能不同。
- **曝光模式**：自动曝光，或手动 ISO + 快门。手动曝光必须同时设置 ISO 与快门；自动对焦和自动白平衡继续由摄像头处理。
- **ISO / 快门**：只要手机提供有效的 ISO 和曝光时间范围，就允许尝试，并限制在所报范围内。30fps 下快门不慢于约 1/30 秒。较快快门减少运动模糊，但会减少进光量。范围为空时不开放手动选项；有范围不代表驱动一定执行请求，须核对顶部实际值及画面变化。
- 开始录制后锁定本段方向，停止后恢复横竖屏切换。
- 录像为 H.264 无声视频，原视频不烧录绿色框。

## 时间与记录机制

- 原始图像路径使用摄像头帧时间戳，以开始向录像编码器发送的第一帧作为零点。时间在取帧时确定，不会使用较晚的识别完成时间。
- PixelCopy 兼容路径按画面复制请求时的录像经过时间记录。预览/编码管线存在延迟，因此对应时间近似，不能保证逐帧精确。
- 正在识别的最后一帧会在停止后写入，再完成索引。未开始识别的屏幕复制请求可能在停止时取消。
- 每次识别出车牌会保存对应小图并原子写入索引。记录只包含成功识别的采样，不保证录像中的每一块车牌都被抓到。
- 回放中的“附近 ± … 秒”依据本段识别间隔计算，不表示整个窗口内车牌始终存在。时间线合并相邻同号记录的显示，CSV 保留各次采样。
- 实时截图来自识别画面（原始流一般最高 720p），录像可以是 4K；不会为获取 4K 截图而在停止后重新解码整段视频。
- 旧录像索引兼容读取。只有用户主动选择手动补扫，才会按当前设置重新生成。

## 保存与限制

- 所有数据保存在应用专属目录，不联网。卸载或清除数据会删除录像，重要录像请先导出。
- 切换应用或锁屏会结束当前录像并保存。本版不做后台持续录像。
- 突然断电或强制结束进程时，已经写入的索引可保留，但 MP4 是否可播放取决于编码器是否正常结束。
- 系统报告支持单个尺寸，不代表每种并行输出组合都保证可用。遇到启动失败请降低分辨率或恢复自动曝光。
- 识别准确率依赖原 SDK、车牌尺寸、清晰度和光照，应结合截图核对。

## 构建与源码

应用源码：`app/src/main/java/cn/platejournal`。

原 SDK Java 接口、ARM 原生库与模型：`vendor/hyperlpr3`。

运行 `bash build.sh`。使用 Android SDK build-tools 36.0.0、android-37.0 平台 jar 和 JDK，不需要 Gradle。可用 `ANDROID_SDK_ROOT` 指定 SDK 根目录、`JAVA_HOME` 指定 JDK。

源码仓库不包含 APK、构建缓存和签名密钥。首次构建会生成新的本地签名，不能覆盖安装由其他密钥签名的版本；更换签名前请先导出录像。

本机构建签名保存在 `.signing/local.jks`，用于后续覆盖升级。不要丢失或公开签名文件。
